

Решали соревнование по адаптивному решению дискретных головоломок. Цель — универсальный алгоритм, который за 50 минут обучения и 25 минут инференса решает любую обратимую головоломку через единый gym.py API.

**Стартовая точка**: baseline с beam search и простым RL-ранжировщиком. Score ~63.

**Что делали по порядку:**

Первым делом разобрались какие паззлы есть: три открытых — пятнашки (SWAP+EMPTY), лампочки (TOGGLE), цилиндр Варикон (ROTATE). Скрытые — того же формата, но неизвестные.

Провели эксперименты со стратегиями и нашли первый реальный баг: константы `CONTENT_NUM/CONTENT_EMPTY` были захардкожены вместо импорта из gym.py.

Для toggle добавили точный GF(2) решатель — система линейных уравнений над полем из двух элементов. Это дало 20/20 инстансов со score 1.52 вместо нуля.

Для пятнашек пробовали IDA* с Manhattan + Linear Conflict. Выяснили что LC для beam — вредит (сужает поиск), а для IDA* — слабо помогает из-за медленного Python. Перешли на инкрементальное обновление Manhattan без LC.

Добавили compact state key вместо JSON — ускорение ~1.5x в hot loops.

Построили reverse BFS таблицу из solved state, но с `max_depth=6` — почти нулевой hit rate.

Починили multiprocessing: PyTorch нельзя загружать до fork(), модель грузится в воркерах после fork. Это убрало RE.

Нашли главный баг в solve.py: beam вызывался только для sliding паззлов (`if sol is None and sliding`). Для цилиндра и скрытых паззлов запускался только A*, который без хорошего V почти ничего не решал. Убрали условие — beam стал fallback для всех типов. Это дало прыжок с 63 до 70.

Потом нашли критический баг в train.py: `max_depth=6` в BFS таблице. Тестовые инстансы генерируются random walk-ом 30-100 шагов, оптимальный путь — 15-40 шагов. Таблица глубиной 6 покрывала ~0% инстансов. Подняли до `max_depth=30`, `max_states=500_000`. Score вырос с 70 до 82.

**Текущее состояние (82)**: таблица покрывает depth ~19-20 и даёт оптимальные решения для попавших инстансов. Beam закрывает остальное но с субоптимальными путями.

**Следующий шаг** который ещё не проверен: table-guided beam — проверять в inner loop beam-а попадание в таблицу. Beam проходит forward 12 шагов, таблица покрывает 20 от solved, combined coverage ~32. Это meet-in-the-middle без дополнительного обучения.
